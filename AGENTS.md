# AGENTS.md

## Рабочий контекст

Это новый независимый проект. Не переносите старый код целиком и не считайте документацию описанием уже работающих функций. До изменений прочитайте `docs/PRODUCT_OVERVIEW.md`, `docs/SCOPE.md`, `docs/ARCHITECTURE.md` и актуальную задачу в `docs/DEVELOPMENT_PLAN.md`.

## Порядок работы

- Выполняйте одну задачу за PR; не расширяйте scope без необходимости.
- Используйте ветки `codex/*`, `kimi/*` или `feature/*`.
- Не делайте commit/push и не меняйте удалённый репозиторий без запроса пользователя.
- Не меняйте независимые части системы ради удобства текущей задачи.
- Не добавляйте Kubernetes, второй orchestrator, multi-agent или новые хранилища без отдельного решения в документации.
- Не добавляйте зависимость, пока не подтверждена её необходимость, совместимость и лицензия.

## Качество

- Код должен соответствовать уже принятой структуре и соглашениям проекта.
- Тесты не должны требовать внешние AI API; используйте fake/deterministic providers.
- Не ослабляйте и не удаляйте существующие тесты ради прохождения CI.
- После изменений запускайте соответствующие проверки и сообщайте фактические результаты.
- Не заявляйте, что GPU, offline или производительность проверены, если проверка не выполнялась.
- При изменении поведения обновляйте затронутые документы и `README.md`.

## Безопасность

- Не добавляйте секреты, `.env`, токены, приватные ключи, модели, production-дампы и реальные данные биржи.
- Не используйте prompt или LLM-guardrail как единственный security boundary.
- ACL проверяются до retrieval и повторно при доступе к содержимому.
- Tool calls валидируются вне модели; опасные действия требуют отдельной политики.
- Сгенерированный код выполняется только в изолированной среде без production credentials.
- Полные prompt/response не логируются по умолчанию.

## Перенос из `rag-mcp-agent`

Переносите только код, относящийся к текущей задаче. Сохраняйте работающие проверенные решения, но адаптируйте их к новым интерфейсам. Не копируйте облачные настройки, старые ограничения, непроверенные ветки и документацию с устаревшими заявлениями.

## Definition of Done

Задача завершена, когда:

1. реализован только заявленный scope;
2. acceptance criteria задачи выполнены;
3. соответствующие тесты и проверки зелёные;
4. документация соответствует поведению;
5. новых непроверенных секретов и внешних зависимостей нет;
6. ограничения и непроверенные части явно перечислены.
