# Границы и критерии POC

## Проблема

Разработчику нужен локальный ассистент, который понимает внутреннюю документацию и исходный код, отвечает с доказательствами и может подготовить проверенное изменение без передачи кода во внешние AI-сервисы.

## Целевая аудитория

- Один основной разработчик платформы.
- Два или три тестировщика на этапе приёмки.
- Домашний ПК с NVIDIA 4070 Ti и 32 ГБ RAM как целевое локальное окружение.

## Входит в POC

1. Локальные HTTP API и MCP для одного движка.
2. Document RAG с hybrid retrieval, источниками и корректным отказом.
3. Сменные provider interfaces для LLM, embeddings и reranker. В текущем коде подключён OpenAI-compatible loopback LLM provider; embeddings пока fake, а reranker interface не подключён к retrieval path. Локальные embeddings и проверенный reranker остаются будущей работой.
4. Пользователи, проектные ACL, rate limits и audit.
5. Индексация синтетического Git-репозитория с AST-метаданными и commit SHA.
6. Coding workflow: task → retrieve → plan → patch → test → review → diff.
7. Git worktree и sandbox без сети и production-секретов.
8. Воспроизводимый benchmark и сценарии для тестировщиков.
9. Docker Compose и runbook для локального запуска.

HTTP API и MCP в этом POC — локальные optional transports, не облачные AI API. HTTP server привязан к loopback; inference provider также обращается только к loopback endpoint. Coding workflow сейчас доступен через CLI. Если интерфейс продукта должен полностью обходиться без HTTP/MCP, эти transports не входят в финальную поверхность продукта и должны оставаться только тестовыми/разработческими адаптерами.

## Не входит в POC

- Production SLA, аппаратная HA и автоматическое масштабирование.
- Реальные данные, ключи и репозитории биржи.
- Непосредственное развёртывание в критичный production.
- Kubernetes, сложный SSO и multi-agent orchestration.
- Обучение базовой модели.
- Обязательный fine-tuning или LoRA.
- Поддержка большого числа языков и репозиториев одновременно.
- Собственный сложный frontend, если достаточно существующего клиента.

## Критерии успеха

- Система устанавливается и запускается по документации без участия автора.
- Ответы содержат проверяемые источники или явный отказ.
- ACL и sandbox проходят предварительно определённые security-тесты.
- Coding agent создаёт реальный diff и запускает реальные тесты.
- Полный контур измеримо сравнивается с baseline на зафиксированном наборе.
- Реальные latency, память и ограничения целевого ПК задокументированы.
- Тестировщики могут дать обоснованное go/conditional-go/no-go для production-пилота.

## Основное допущение

POC доказывает архитектуру, безопасность сценариев и полезность на небольшом наборе задач. Он не доказывает производительность 100 разработчиков и готовность к эксплуатации финансовой инфраструктуры.
