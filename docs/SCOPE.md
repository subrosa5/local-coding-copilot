# Границы проекта

## Целевой продукт

Закрытый coding assistant для команды криптобиржи: ориентир — около 10 проектов и до 10 разработчиков в каждом. Ассистент ищет по внутренней документации и коду, отвечает со ссылками, готовит небольшие patches и запускает проверки в изоляции. Исходный код, запросы и модели остаются внутри инфраструктуры компании; внешние AI-сервисы не используются.

Это целевая аудитория и направление архитектуры, не подтверждённая пропускная способность текущей системы.

## Текущая цель

Проверить вертикальный сценарий на домашнем оборудовании и синтетических данных до выделения ресурсов на enterprise-пилот. Ближайшие пользователи POC — автор и 2–3 тестировщика. До реальных данных нужно закрыть M7 hardware/model gate и провести M8 приёмку.

## Входит в POC

- Document RAG и Python Code RAG с commit-aware citations.
- Проектные роли/ACL и технический audit.
- Provider seam для локальной LLM; текущая embedding реализация остаётся fake.
- Coding CLI, detached Git worktree, patch validation, Docker compileall/unittest и bounded repair.
- Benchmark harness, синтетический набор задач и инструкции тестировщику.
- Локальный запуск с PostgreSQL/pgvector и Docker Compose.

## Не считается реализованным

- Реальные локальные embeddings и проверенное качество vector retrieval.
- Подключённый reranker.
- Проверка конкретной coding-модели, GPU, latency, VRAM/RAM и offline.
- Расширенный benchmark с независимыми acceptance tests.
- Корпоративный SSO, удобный lifecycle пользователей и distributed quotas.
- IDE plugin/desktop UI, inference pool, очереди, HA, нагрузочная ёмкость на 100 пользователей.
- Enterprise-grade sandbox и разрешение на production repositories/secrets.

## Интерфейсы и закрытый контур

POC содержит local HTTP и MCP adapters для query функций и CLI для coding workflow. Они не обращаются к облачным AI API. Конечный пользовательский интерфейс ещё не выбран; если продукт должен обходиться без HTTP/MCP, эти adapters остаются только вспомогательными интерфейсами разработки. Внутреннее соединение с self-hosted inference — допустимая часть закрытой сети, если оно не выходит во внешний сервис.

## Критерии для решения о пилоте

- Реальная локальная модель и embeddings проверены на целевом оборудовании; offline сценарий повторён.
- ACL, sandbox, prompt injection, ресурсы и логи проходят заранее определённые security gates.
- Coding benchmark использует независимые acceptance tests, а пороги приняты до измерений.
- Фактические качество, latency, ресурсы и human acceptance задокументированы.
- 2–3 тестировщика проходят одинаковые сценарии без помощи автора.
- Есть отдельный security/architecture review и письменное решение для ограниченного пилота.

Успех POC не означает готовность к критичным production системам и не доказывает поддержку 100 разработчиков.
